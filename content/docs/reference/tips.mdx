这一页收可以马上抄走的小做法，每条只讲一件事：怎么做、风险在哪、出处在哪。要系统地配环境，看[快速开始](/docs/quickstart)和[三层护栏](/docs/guardrails)；更多随手记在我的 X：[@NeoJubao](https://x.com/NeoJubao)。

## 给 Claude Code 和 Codex 设快捷入口

<Evidence kind="lived" /> 免确认模式的参数太长，在 `~/.zshrc` 里写成短命令，改完运行 `source ~/.zshrc`。目录换成你自己的工作目录：

```bash
ccp() {
  [[ "$PWD" == "$HOME" ]] && { cd ~/projects || return; }
  claude --dangerously-skip-permissions "$@"
}
alias cx='codex --dangerously-bypass-approvals-and-sandbox'
```

第二行让 `ccp` 不在家目录里启动：那里有 SSH 配置、云账号凭证和各种配置文件。`"$@"` 把参数原样传下去，`ccp -c` 就是继续上次会话。

<Callout type="warn" title="先看风险">
“只在信任的项目里用”还不够，还要看两件事：agent 会不会读到不可信的内容（网页、邮件、别人提的 issue），机器上有没有明文凭证。三样凑齐时不要开免确认（见[agent 读得到的凭证，就当已经暴露](/docs/pitfalls/credentials-agent-can-read)）。Codex 这个参数连沙箱也一起关掉，`--help` 里写明它只适合外部已经隔离的环境。
</Callout>

开之前先配好[最小护栏](/docs/tool/guardrails)的 deny 规则。我自己就踩过这个坑：发现 deny 规则丢了之后，过了两周才补回来，这期间我一直配着 `ccp`（见[防护规则会悄悄失效](/docs/pitfalls/guardrails-decay)）。

<Evidence kind="industry" /> 想少弹窗又不想全放开，官方更推荐 auto 模式：`claude --permission-mode auto`，由分类器在后台审查每个动作。我自己还没有长期用过。

出处：[我的 X 回复](https://x.com/NeoJubao/status/2114638486645129597)（2026-10-26）。

## 给 agent 接 Slack 和邮箱之前，先开个只读小号

<Evidence kind="industry" /> 我在 Web3 那几年见过的被盗，很多是从员工电脑、第三方插件、客服后台进来的，合约本身反而最难打。agent 也一样：第一步不要把你的主账号交给它，先开一个只读的小号，确认它真的需要写权限，再逐项放开。这是我的判断，还没有在 agent 上做过完整验证。

出处：[我的 X 帖子](https://x.com/NeoJubao/status/2116008644894732419)（2026-10-30）。

## 验证 CDN 上的文件，别用 HEAD

<Evidence kind="lived" /> 我用 `curl -I` 验证安装包，自建的缓存 Worker 把 HEAD 的空响应存进了 GET 的缓存键，后面的下载全拿到 0 字节。所以这类地址一律用 GET 验证，看状态码和字节数：

```bash
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' "$URL"
```

缓存已经被污染时，换一个缓存版本号再清边缘缓存。自己写 Worker 时，缓存逻辑只处理 GET。

## 让 agent 写批量脚本时，把配对写死

<Evidence kind="lived" /> 批量上传时，文件名和地址要一一对应。agent 用 zsh 循环拼这两列，我踩过两次：zsh 数组从 1 开始，`files[0]` 是空串，整列错开一位；`set -- $PAIR` 在 zsh 里默认不拆词。一次性脚本不值得调，让 agent 直接写死成一行一对：

```bash
upload() { echo "upload $1 -> $2"; }
upload app-arm64.dmg https://example.com/signed-url-1
upload app-x64.dmg https://example.com/signed-url-2
```
